# 职场降落伞 H5：UI/UX 结构性优化设计规格

日期：2026-06-12  
状态：方向已确认，待用户审阅书面规格  
目标仓库：`Rucia616/layoff-helper`  
部署目标：GitHub Pages `https://rucia616.github.io/layoff-helper/`

## 1. 问题诊断

当前线上版已经可交互，但 UI/UX 不够好，核心问题不是单个颜色或字号，而是产品链路不够顺：

- 首屏像“红色热测活动页”，但没有足够专业信任感。
- 视觉重点太大太满，用户第一眼知道能测，但不知道为什么值得测。
- 结果页出现“结果卡”和“分享卡”两套重复表达，阅读负担高。
- 证据清单像表单列表，用户看到后容易觉得麻烦。
- “小红书传播感”和“职场权益工具可信感”没有分层，导致既不够收藏，也不够专业。

## 2. 新方向

改成“职场体检报告感”：

> 像小红书里一篇值得收藏的实用笔记，又像一份轻量、可信、能行动的职场体检报告。

设计关键词：

- 小红书：可截图、可分享、有结果标签、有收藏价值。
- 专业：体检报告结构、清晰风险解释、明确下一步。
- 温暖：不恐吓，不制造“马上完蛋”的焦虑。
- 高级：少装饰、少大渐变、少重复卡片，靠排版和节奏建立质感。

## 3. 信息架构

整体仍然是静态单页应用，保留现有功能，但重排用户路径：

1. `首页 / 测前动机`
   - 目标：让用户明白“我为什么现在要测”。
   - 不再用整屏大渐变压迫用户。
   - 第一屏包含：产品名、风险体检主题、主 CTA、隐私说明、结果样例预览。

2. `轻量答题`
   - 目标：让用户快速完成，不被问卷感劝退。
   - 每题像聊天式选择，而不是考试表单。
   - 固定底部下一题按钮，减少滚动找按钮。

3. `体检报告结果`
   - 目标：让用户理解自己的状态，并愿意继续行动。
   - 合并当前结果卡和结果说明。
   - 首屏展示：灯色、分数、人格标签、一句话解释、三个关键风险信号、两个 CTA。

4. `分享卡`
   - 目标：形成传播。
   - 作为结果页下方的独立海报，不重复整段报告。
   - 只展示：标签、灯色、分数段、行动金句、产品名和链接位。

5. `优先行动`
   - 目标：把焦虑转成 3 个马上能做的动作。
   - 结果页直接给 3 个优先动作：合同、工资流水、绩效/沟通记录。
   - 完整清单作为展开或进入下一页。

6. `应急模式`
   - 目标：服务已经被约谈的人。
   - 继续保留“被约谈了，先别签”，但视觉改成冷静的步骤卡，不再像普通文章。

## 4. 首屏设计

首屏从“活动海报”改成“体检报告入口”。

结构：

- 顶部品牌行：`职场降落伞`
- 小标题：`裁员风险体检`
- 主标题：`先测风险，再准备证据`
- 副文案：`9 个问题，看清公司信号、个人处境和现在最该做的事。`
- 主 CTA：`开始体检`
- 次入口：`已经被约谈？先看应急`
- 轻量信任：`不登录 · 不上传 · 结果只存在本机`
- 右侧或下方：一个“体检报告预览”小卡，不再使用倾斜大卡和大伞占据空间。

视觉：

- 背景以纸白为主，局部使用淡红/淡黄状态块。
- 红色只服务 CTA、状态标签和关键提示。
- 首页第一屏必须在 375x812 内完整看到主 CTA。
- 允许露出下一段“你会得到什么”，帮助用户继续下滑。

## 5. 答题 UX

当前问卷可以保留 9 题，但交互要更轻。

要求：

- 题目区上方显示：`第 X 题 / 9`
- 进度条更细、更克制。
- 选项像对话气泡/选择条，减少“考试”感。
- 选择后自动高亮，但不自动跳题，避免误触。
- 底部 CTA 固定为 `下一题` / `查看报告`。
- 上一题保留为小文字入口，不和主按钮同等视觉权重。

## 6. 结果报告

结果页主模块改成“一份报告”，不再上下重复。

内容顺序：

1. `你的风险体检报告`
2. 分数 + 灯色
3. 类型标签，例如 `绩效安全，但公司危险型`
4. 一句话解释
5. 三个关键信号
6. 三个优先行动
7. CTA：`生成分享卡`、`开始存证据`

结果语气：

- 绿灯：别松懈，做低成本准备。
- 黄灯：最佳备战窗口。
- 红灯：先稳住，不要签字，优先补证据。

## 7. 分享卡

分享卡要像一张小红书封面，而不是报告截图。

规格：

- 比例接近 3:4。
- 更少文字，更强标签。
- 不展示具体答案，不展示公司信息。
- 三种状态视觉不同：
  - 绿灯：清爽、安心、低成本准备。
  - 黄灯：黄/红点题，强调风向变化。
  - 红灯：克制警示，不使用恐吓大红。

分享卡文案示例：

- `我是黄灯打工人`
- `绩效还稳，但公司风向变了`
- `不是制造焦虑，是提醒自己别空手上谈判桌`

## 8. 证据清单

证据清单从“完整表单”改为“行动优先”。

页面顶部：

- 标题：`先存这 3 项`
- 副文案：`这些最影响补偿基数和谈判筹码。`
- 三个优先项在最前：劳动合同、工资流水、绩效/沟通记录。

完整清单：

- 仍保留 7 项。
- 每项显示：名称、为什么重要、完成状态、备注。
- 备注输入弱化，默认不是视觉主角。
- 完成一项后给轻反馈，不用夸张庆祝。

## 9. 应急模式

应急页保持 4 步，但改成更强 UX：

- 顶部固定显示当前步骤。
- 每步只保留一个主动作。
- 话术卡更突出，可复制。
- 赔偿计算器保留，输入标签清晰，错误提示内联。

## 10. 视觉系统

色彩：

- 背景：`#fbfaf7` 或接近纸白。
- 主文字：`#1d1d1f`。
- 辅助文字：`#6e6862`。
- 主红：`#ff2442`，只用于 CTA 和关键状态。
- 状态黄：更克制的暖黄，不大面积铺满。
- 状态绿：低饱和绿色。

排版：

- 不使用超大四行标题。
- 首屏标题最多 2-3 行。
- 卡片内标题收紧，不用 hero 级字号。
- 数字使用 tabular figures。

组件：

- 卡片半径统一 12px。
- 按钮 12px 半径，不全页面 pill。
- 不做倾斜大卡作为主视觉。
- 不使用大面积深紫到橙色渐变。

## 11. 技术边界

保留当前静态技术栈：

- `index.html`
- `style.css`
- `app.js`
- `tests/xhs-model.test.mjs`

不新增框架，不新增后端，不强制登录。

允许调整：

- 页面结构
- CSS 设计系统
- 结果页渲染
- 证据清单排序和呈现方式
- 应急步骤 UI

保留：

- 9 题问卷逻辑
- 绿/黄/红分段
- localStorage 本机保存
- 复制分享文案
- GitHub Pages 部署到 `Rucia616`

## 12. 验收标准

UI：

- 375x812 首屏能完整看到主 CTA。
- 页面不再像整屏促销海报。
- 结果报告和分享卡不重复。
- 证据清单第一眼能看出“先做哪 3 件事”。

UX：

- 用户从首页到完成问卷不需要理解复杂导航。
- 结果页下一步明确。
- 分享卡适合截图。
- 应急模式不吓人，但足够明确。

技术：

- `node --check app.js` 通过。
- `node --test tests/xhs-model.test.mjs` 通过。
- 本地 Playwright 验证核心流程。
- 部署到 `https://rucia616.github.io/layoff-helper/`。
- 线上 Playwright 验证核心流程。

## 13. 非目标

本轮不做：

- 后端服务。
- 真实二维码生成服务。
- 用户账号。
- 付费转化。
- AI 法律咨询。
- 小红书平台 API。

## 14. 自检

- 方向聚焦在 UI/UX 结构性优化，不是单纯换色。
- 传播入口、结果报告、行动清单三者分工明确。
- 隐私和法律免责声明保留。
- 范围适合一次前端迭代完成。
