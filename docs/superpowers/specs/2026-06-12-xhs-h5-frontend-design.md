# 职场降落伞：小红书 H5 引流前端设计规格

日期：2026-06-12  
状态：设计已确认，待用户审阅书面规格  
依据：用户确认 `xhs-style-v2` 方向，“这版小红书感可以”

## 1. 目标

把现有「裁员赔偿谈判助手」前端改成一个移动端优先的病毒 H5：

- 第一入口从“工具导航”改为“裁员可能性 / 职场降落伞热测”。
- 用小红书式标题、结果卡和分享动机拉新。
- 用证据清单、谈判指引和隐私承诺承接用户的真实行动。
- 保持温暖、专业、可信，不做恐吓式营销，不暗示测评能预测真实裁员结果。

一句话定位：

> 先用一个愿意分享的裁员风险热测把用户带进来，再把焦虑转成可执行的证据准备和谈判行动。

## 2. 设计原则

1. 小红书感放在入口和分享层，工具层保持专业。
2. 文案可以有网感，但每个结果都必须给出下一步行动。
3. 视觉要暖、轻、清醒，避免政务感、律师函感、塔罗感。
4. 风险表达使用“信号”“可能性”“建议准备”，不使用“预测”“一定会裁”“稳赢赔偿”。
5. 所有数据默认本机保存，不上传，不要求登录。

## 3. 信息架构

页面仍保持单页应用，核心流改为：

1. `H5 首屏`
   - 用户看到热测主题、社交化标题、隐私提示和主 CTA。
   - 主 CTA：开始 2 分钟自测。
   - 次 CTA：已经被约谈，直接看应对。

2. `裁员可能性自测`
   - 默认走轻量版 8-9 题，适合 H5 传播。
   - 原有 14 题评分维度保留为数据基础，后续可提供“深度版”入口。
   - 题目按公司信号、个人处境、行业信号、近期异常分组，但用户感知上是一条顺滑问卷。

3. `结果页`
   - 输出绿灯 / 黄灯 / 红灯。
   - 输出一个更适合分享的用户类型，例如：
     - 绿灯：安全垫还在，但别空手上班型
     - 黄灯：绩效安全，但公司危险型
     - 红灯：信号叠满，马上备战型
   - 显示 3 个最关键触发信号。
   - 给出两个主要动作：生成结果卡、开始存证据。

4. `分享结果卡`
   - 作为结果页内的独立卡片区，不需要登录。
   - 适合截图保存，也可接 Web Share API。
   - 分享卡不展示用户具体答案，只展示分数段、类型、行动建议和产品名。

5. `证据清单承接`
   - 从“证据保险箱”改成更轻的小红书承接表达：我的降落伞清单。
   - 保留合同、工资流水、奖金提成、加班、社保公积金、绩效沟通、工作成果等条目。
   - 保留本机保存和完成进度。

6. `HR 约谈应急`
   - 作为红灯结果和首页次入口的强承接。
   - 名称从“实战谈判指引”可调整为“被约谈了，先别签”。
   - 内容继续强调参考信息，不构成法律意见。

## 4. 首屏规格

首屏必须一眼看出是“裁员可能性热测”，不是普通工具首页。

建议结构：

- 顶部小标签：`职场热测`
- 主标题：`你的职场降落伞打开了吗？`
- 副标题：`测一测：未来一段时间，你该不该提前备战裁员。`
- 信任提示：`不上传数据 · 只给你自己看 · 可生成结果卡`
- 主按钮：`开始 2 分钟自测`
- 次按钮：`已经被约谈？直接看应对`
- 首屏底部露出下一段内容，让用户知道后面不是空页面。

视觉要求：

- 移动端首屏优先，375px 宽度下主 CTA 不得被折到不可见区域。
- 不使用大段说明文字，不使用工具导航卡作为第一视觉。
- 可以保留“降落伞”隐喻，但它必须服务 H5 主题，不再占据过强的品牌官网感。
- 如果继续使用降落伞插画，建议小型化为结果卡/角标元素，而不是整屏插画主角。

## 5. 视觉系统

整体方向：小红书热测封面 + 职场工具可信界面。

颜色：

- 主行动色：小红书红 `#FF2442` 或接近色。
- 文字主色：墨黑 `#1D1D1F`。
- 背景：温暖纸白 `#FAF7F2`，搭配少量纯白模块。
- 状态色：绿灯、黄灯、红灯继续服务风险表达。
- 辅助色可加入低饱和蓝灰、鼠尾草绿，避免页面只剩红和米色。

版式：

- 卡片半径以 8px 为主，结果海报可略大但必须克制。
- 字号层级清楚：H5 标题大，工具区标题收紧。
- 不使用大面积紫蓝渐变、深蓝黑科技、政务蓝、律师风金色。
- 避免装饰性光斑和无意义背景元素。

小红书感的边界：

- 可以使用“热测”“我的结果”“黄灯打工人”等社交语言。
- 不使用过多 emoji。
- 不做夸张贴纸堆叠，不做低可信营销弹窗。
- 分享卡可以更活泼，证据清单必须更沉稳。

## 6. 核心组件

### 6.1 H5 Hero

职责：完成“我愿意开始测”的第一转化。

内容：

- 主题标签
- 标题
- 3 个短利益点
- 主 CTA
- 应急次 CTA

状态：

- 首次访问
- 已有上次结果时，显示“继续查看我的结果”
- 已有证据清单进度时，显示轻提示“你已完成 X 项准备”

### 6.2 Quiz Question

职责：让用户快速完成测评。

要求：

- 题卡保持一屏内优先完成阅读和选择。
- 进度条明确显示 `第 X / Y 题`。
- 选项按钮点击区域不少于 44px 高。
- 下一题按钮只有选择后可用。
- 上一题保留，但弱化。

题目语气：

- 原问题保留专业含义，表达更接近真实用户语言。
- 例如“公司近期是否有这些动作”可以改为“最近公司有没有这些风向？”
- 不牺牲评分准确性换取标题党。

### 6.3 Result Note

职责：让用户理解风险，也愿意截图分享。

结果页首屏内容：

- `我的结果`
- 分数和灯色，例如 `64 黄灯`
- 类型标题，例如 `绩效安全，但公司危险型`
- 一句解释
- 3 个触发信号
- 主 CTA：`生成我的结果卡`
- 次 CTA：`开始存证据`

结果文案规则：

- 绿灯：强调“现在平稳，但可以低成本准备”。
- 黄灯：强调“现在是最佳备战窗口”。
- 红灯：强调“先稳住，不要马上签字，先补证据和看应对”。

### 6.4 Share Poster

职责：形成传播闭环。

规格：

- 3:4 或接近小红书封面比例。
- 内容只展示结果等级、类型、行动建议、产品名和二维码/链接区域。
- 不展示具体答案、公司信息、个人备注。
- 提供 `保存结果卡` 和 `复制分享文案` 两个动作。

分享文案示例：

- `我测出来是黄灯：绩效还稳，但公司信号有点危险。先给自己备个降落伞。`
- `不是制造焦虑，是提醒自己别空手上谈判桌。`
- `测完才发现，真正该准备的是证据，不是情绪。`

### 6.5 Evidence Checklist

职责：把传播流量转成留存和行动。

名称建议：`我的降落伞清单`

内容：

- 当前准备进度
- 7 类证据清单
- 每项包含“为什么重要”和“我存在哪里”
- 本机保存提示

交互：

- 勾选完成
- 备注保存到 localStorage
- 从结果页进入时，自动高亮最优先的 3 项：劳动合同、工资流水、绩效/沟通记录。

### 6.6 Emergency Guide

职责：服务已经被约谈或红灯高风险用户。

名称建议：`被约谈了，先别签`

内容结构：

- 先做什么：不当场签、要求带走材料、确认解除理由。
- 怎么说：保留现有话术卡片。
- 怎么算：赔偿基数和 N/N+1 的基础解释。
- 何时找专业帮助：金额大、证据复杂、公司违法解除争议明显。

## 7. 数据与隐私

继续使用纯前端和 localStorage：

- 自测答案：可只保留最近一次结果，不长期保存明细。
- 证据清单：保留完成状态和备注。
- 分享卡：只由当前结果生成，不上传。

必须显示：

- `你的数据只存在这台设备上，不上传、不联网。`
- `本工具提供参考信息，不构成法律意见。`

不得新增：

- 强制登录
- 手机号收集
- 公司名收集
- 默认上传截图或备注

## 8. 实现边界

本轮前端优化应保持轻量：

- 继续使用现有 `index.html`、`style.css`、`app.js` 结构。
- 不引入复杂框架。
- 可以重组页面结构、CSS 变量、问题展示、结果展示和分享卡生成。
- 不做后端、不做真实二维码服务、不做小红书平台接口。
- Web Share API 只作为增强能力；不支持时提供复制文案和截图保存引导。

## 9. 验收标准

视觉验收：

- 375x812、390x844、430x932 下无文字重叠。
- 首屏能直接看到主标题、主 CTA 和至少一个信任提示。
- 结果分享卡完整出现在一屏内，适合截图。
- 证据清单看起来像可信工具，不像营销落地页。

功能验收：

- 自测可完整走完并得到绿/黄/红结果。
- 结果页能进入证据清单和应急指引。
- 证据清单勾选和备注刷新后仍保留。
- 重新测一次能重置问卷状态。
- Web Share 不可用时，复制分享文案功能可用。

体验验收：

- 默认问卷完成时间控制在 2 分钟内。
- 用户看到结果后，下一步行动明确。
- 分享卡不泄露具体回答、公司信息或备注。
- 页面动效轻，不影响阅读和低端手机性能。

## 10. 测试计划

实现后用浏览器验证：

- 移动端视口：375x812、390x844、430x932。
- 桌面视口：1280x800，确认移动容器居中且背景不抢戏。
- 完整流程：首屏 -> 问卷 -> 结果 -> 分享卡 -> 证据清单 -> 返回。
- localStorage：勾选和备注持久化。
- 降级路径：禁用 Web Share API 时仍可复制文案。
- 可访问性：按钮焦点可见、触控区域足够、减少动态效果时无关键内容丢失。

## 11. 非目标

本轮不做：

- 真实社交平台发布接口。
- AI 法律咨询。
- 用户账号系统。
- 付费转化页。
- 复杂数据看板。
- 对裁员概率做确定性预测。

## 12. 自检

- 无未确定功能。
- 传播入口和专业工具承接已经分层。
- 隐私和法律免责声明保留。
- 规格可在当前静态前端内实现。
- 范围足够聚焦，可进入下一步实现计划。
